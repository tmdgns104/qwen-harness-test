# QH-V2-002 - Deterministic Evidence Collector

## Status

`APPROVED - READY FOR IMPLEMENTATION`

## Goal

Create a small deterministic Evidence Collector that gathers repository verification evidence without relying on an LLM.

The collector must provide objective Git and file-change evidence that can later be given to a simplified Verifier.

## Problem

Harness V1 required Qwen to perform and interpret too many verification operations.

Observed failures included:

- skipped verification reads;
- false PASS results;
- incorrect file-change interpretation;
- repeated tool calls;
- path hallucination;
- unnecessary LLM reasoning for deterministic Git facts.

Git and deterministic code should gather these facts instead.

## Scope

Implement a standalone Evidence Collector inside the qwen-harness-test repository.

The collector receives:

- repository root;
- exact Task file path;
- Git HEAD as the verification baseline.

The collector reads the Task specification and gathers objective repository evidence.

## V2 Initial Scope

The initial collector handles:

- Task file existence;
- current Git HEAD;
- changed tracked files;
- untracked files;
- Git status;
- per-file Git diff;
- Allowed Changes patterns;
- Forbidden Changes patterns;
- changed-file scope violations.

It does NOT decide whether the Task passed.

It only gathers Evidence.

## Task Contract Parsing

Read these Task sections when present:

- `## Allowed Changes`
- `## Forbidden Changes`

Extract repository path entries from Markdown bullet items.

The initial pattern contract must support at minimum:

- exact file paths
  - `DECISIONS.md`
  - `STATUS.md`

- directory recursive patterns
  - `src/**`
  - `tests/**`
  - `results/**`

Do not infer additional allowed or forbidden paths.

If the Task cannot be parsed safely, record an error instead of guessing.

## Git Baseline

Use the current committed `HEAD` as the pre-implementation baseline.

Collect:

- HEAD commit SHA;
- `git status --short`;
- changed tracked files;
- untracked files;
- `git diff HEAD --name-status`;
- per-file diff from HEAD.

The collector must never:

- commit;
- stage;
- restore;
- reset;
- checkout;
- clean;
- alter Git history.

## Evidence Output

Produce structured JSON.

Minimum schema:

```json
{
  "schema_version": "1.0",
  "task_path": "tasks/TASK-005C.md",
  "baseline_head": "abc123",
  "git_repository": true,
  "allowed_patterns": [],
  "forbidden_patterns": [],
  "changed_files": [],
  "scope_violations": [],
  "collector_errors": []
}
