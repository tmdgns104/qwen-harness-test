# QH-V2-002 - Deterministic Evidence Collector

## Status

`APPROVED - READY FOR IMPLEMENTATION`

## Goal

Qwen의 검증 주장에 의존하지 않고,
Git과 Python으로 Task 수행 결과의 객관적인 Evidence를 수집한다.

## Problem

Qwen Worker는 실제로 확인하지 않은 파일도
"검증했다", "변경되지 않았다"고 보고할 수 있다.

파일 변경 여부와 Task Scope 준수 여부는
LLM이 아니라 deterministic code가 확인한다.

## Scope

작은 Python Evidence Collector를 구현한다.

입력:

- Repository root
- 정확한 Task file path

수집:

- Task의 Allowed Changes
- Task의 Forbidden Changes
- Git HEAD 대비 실제 changed files
- Scope violation

출력:

- JSON Evidence

Collector는 최종 PASS / FAIL을 판단하지 않는다.

## Required Behavior

Task에서 다음 Section을 읽는다.

- `## Allowed Changes`
- `## Forbidden Changes`

최소 다음 경로 형식을 지원한다.

Exact path:

- `target.txt`
- `DECISIONS.md`

Recursive directory:

- `src/**`
- `tests/**`

현재 committed Git HEAD를 baseline으로 사용한다.

실제 changed file마다 다음 사실을 기록한다.

- file path
- Git status
- Allowed Changes와 일치하는가
- Forbidden Changes와 일치하는가

다음 경우 Scope violation으로 기록한다.

- Forbidden Changes에 포함된 파일이 변경됨
- Allowed Changes가 존재하는데 그 범위 밖의 파일이 변경됨

## Rules

- Task에 없는 path를 임의로 추론하지 않는다.
- Repository 상태를 수정하지 않는다.
- `git add`를 실행하지 않는다.
- `git commit`을 실행하지 않는다.
- `git restore`를 실행하지 않는다.
- `git reset`을 실행하지 않는다.
- 최종 Task PASS / FAIL을 판단하지 않는다.
- Evidence 사실만 수집한다.
- Qwen 또는 다른 LLM을 사용하지 않는다.
- third-party dependency를 추가하지 않는다.

## Output

출력은 valid JSON이어야 한다.

최소한 다음 정보를 포함한다.

- schema_version
- task_path
- baseline_head
- allowed_changes
- forbidden_changes
- changed_files
- scope_violations
- collector_errors

## Allowed Changes

- `tools/evidence_collector.py`
- `tests/test_evidence_collector.py`

## Forbidden Changes

- 기존 Harness Agent 파일
- 기존 Harness Command 파일
- 기존 Task 파일
- Personal Engineering Brain Repository
- LangGraph
- LangChain

## Acceptance Criteria

- 정확한 Task file path를 입력받는다.
- Allowed Changes를 읽는다.
- Forbidden Changes를 읽는다.
- Git HEAD SHA를 읽는다.
- Git HEAD 대비 changed files를 수집한다.
- exact path matching이 동작한다.
- `directory/**` matching이 동작한다.
- Forbidden 변경을 Scope violation으로 기록한다.
- Allowed 범위 밖 변경을 Scope violation으로 기록한다.
- clean Repository도 정상 처리한다.
- valid JSON을 출력한다.
- Repository 상태를 변경하지 않는다.
- third-party dependency를 추가하지 않는다.

## Verification

자동 Test로 최소 다음을 검증한다.

1. Allowed 파일만 변경
2. Forbidden 파일 변경
3. Allowed 범위 밖 파일 변경
4. `directory/**` matching
5. clean Repository
6. valid JSON output

Evidence Collector Test를 실행한다.

마지막으로 `D:\qwen-harness-test`에서 read-only smoke test를 1회 수행한다.

## Out of Scope

이번 Task에서는 다음을 구현하지 않는다.

- 최종 PASS / FAIL 판단
- Qwen Verifier V2
- Task별 pytest 자동 실행
- Retry workflow
- LangGraph
- LangChain
- Codex integration
- TASK-005C 실행
