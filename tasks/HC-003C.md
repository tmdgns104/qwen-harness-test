## Problem

The Harness Core can capture a clean Git baseline but cannot yet deterministically report actual Repository paths changed after that baseline. Worker self-report must not be used as changed-file Evidence.

## Goal

Implement deterministic changed-path Evidence from `baseline.head` to current Repository state.

## Required API

`def get_changed_paths(repo_root: str, baseline: GitBaseline) -> tuple[str, ...]: ...`

## Changed-Path Contract

`get_changed_paths()` must:
- require the actual Git top-level via existing HC-003A root validation;
- compare tracked changes to `baseline.head`;
- return `()` when unchanged;
- include modified tracked, staged changes and staged additions, committed-after-baseline, deleted, and untracked non-ignored paths;
- exclude ignored untracked paths;
- report both old and new paths for renames by disabling rename detection;
- keep tracked paths as Evidence even if later matching ignore rules;
- return Repository-relative `/` paths, unique and deterministically sorted;
- preserve spaces exactly;
- fail closed with `RuntimeError` for invalid/unavailable `baseline.head` or required Git failures;
- never modify Repository state.

## Git Command Boundary

Reuse `_run_git()` and `_require_git_top_level()`.
Use Python standard-library process execution only.
Git commands returning path lists must use NUL-delimited output (`-z`).
Do not parse Git path lists with whitespace or line splitting.
Disable rename detection for tracked changed-path collection.
Do not invoke shell command strings or mutating Git commands.
