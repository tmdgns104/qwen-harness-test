# HC-003B - Clean Git Baseline Capture

## Status

APPROVED - READY FOR CONTRACT BASELINE PREPARATION

## Parent Task

HC-003 - Git Baseline and Changed-File Evidence

HC-003 was decomposed after objective Worker failures.

HC-003A implemented the shared Git execution and Repository-root validation primitives.

HC-003B implements only clean Git baseline capture.

HC-003C will implement changed-path Evidence.

## Problem

HC-003A can execute required read-only Git commands and deterministically validate that the supplied `repo_root` is the actual top-level directory of the Git worktree.

The Harness Core still cannot deterministically capture a clean Git baseline before Worker execution.

Worker execution must never begin from a dirty Repository because pre-existing changes would make later changed-file Evidence ambiguous.

Baseline cleanliness must therefore be determined mechanically from Git state rather than from Worker self-report.

## Goal

Add a frozen Git baseline value and a public baseline-capture function that:

* requires the actual Git top-level Repository root;

* captures the current `HEAD` commit;

* accepts only a clean Repository state;

* rejects tracked unstaged changes;

* rejects staged changes or staged additions;

* rejects untracked non-ignored files;

* ignores untracked files excluded by standard Git ignore rules;

* fails closed when required Git operations fail;

* never modifies Repository state.

Do not implement changed-path Evidence in this Task.

## Required API

```python

@dataclass(frozen=True)

class GitBaseline:

    head: str

def capture_git_baseline(repo_root: str) -> GitBaseline:

    ...

```

## Baseline Contract

`GitBaseline` must:

* be a frozen dataclass;

* contain the captured Git `HEAD` commit in `head`;

* not contain Worker self-report or mutable Repository state.

`capture_git_baseline()` must:

* use the HC-003A Repository-root validation primitive rather than implementing a separate root check;

* require `repo_root` to be the actual top-level directory of the Git worktree;

* reject a valid worktree subdirectory with `ValueError`;

* surface a non-Repository path or required Git command failure as `RuntimeError`;

* identify the current `HEAD` commit;

* reject any tracked unstaged modification;

* reject any staged modification, addition, or deletion;

* reject any untracked non-ignored path;

* ignore untracked files excluded by standard Git ignore rules;

* return `GitBaseline(head=<current HEAD>)` only when the Repository is clean under this contract;

* never modify the index, working tree, HEAD, refs, ignore rules, or any Repository file.

## Cleanliness Boundary

For HC-003B, a Repository is clean only when all of the following are absent:

* tracked unstaged changes;

* staged changes;

* staged additions;

* staged deletions;

* untracked non-ignored paths.

The following does not make the Repository dirty:

* untracked files ignored by standard Git ignore rules.

HC-003B does not decide whether changed paths are allowed or forbidden.

HC-002 owns path-scope decisions.

## Git Command Boundary

Use the HC-003A `_run_git()` helper for required Git execution.

Use Python standard-library process execution only.

Do not:

* invoke shell command strings;

* run Git commands that modify Repository state;

* use Worker output as cleanliness Evidence;

* silently treat Git failures as a clean Repository.

Required Git failures must fail closed as `RuntimeError`.

## Scope

Do not implement:

* `get_changed_paths()`;

* tracked changes relative to an older baseline;

* committed-after-baseline detection;

* NUL-delimited changed-path parsing;

* rename Evidence;

* deleted-path Evidence collection;

* Repository-relative changed-path normalization;

* scope PASS/FAIL decisions;

* verification command execution;

* exact/hash invariant checks;

* Evidence JSON assembly;

* final PASS/FAIL gate;

* Worker execution;

* CLI behavior;

* HC-003C;

* HC-004 or later behavior.
