# HC-003 - Git Baseline and Changed-File Evidence

## Status

APPROVED - READY FOR CONTRACT BASELINE PREPARATION

## Problem

HC-001 parses Task change-scope contracts and HC-002 decides whether a Repository-relative path is allowed or forbidden, but the Harness Core does not yet have deterministic Git Evidence for the clean baseline before Worker execution and the actual paths changed after execution.

Worker self-report must not be used as changed-file Evidence.

## Goal

Add deterministic Git Evidence that captures a clean Git HEAD baseline and reports all Repository-relative paths changed from that baseline, including untracked paths.

HC-003 does not decide whether paths are allowed. HC-002 owns that decision.

## Required API

```python
@dataclass(frozen=True)
class GitBaseline:
    head: str

def capture_git_baseline(repo_root: str) -> GitBaseline:
    ...

def get_changed_paths(repo_root: str, baseline: GitBaseline) -> tuple[str, ...]:
    ...
```

## Baseline Contract

`capture_git_baseline()` must:

- require `repo_root` to be the actual top-level directory of the Git worktree; a Repository subdirectory is not accepted as the Repository root;
- identify the current `HEAD` commit;
- reject tracked, staged, unstaged, or untracked non-ignored changes with `ValueError`;
- ignore ignored files when determining cleanliness;
- surface required Git command failures as `RuntimeError`;
- never modify Repository state.

## Changed-Path Contract

`get_changed_paths()` must require `repo_root` to be the actual top-level directory of the Git worktree and must report paths changed from `baseline.head` to the current Repository state, including:

- modified tracked files;
- staged changes and staged additions;
- untracked non-ignored files;
- deleted tracked files;
- both old and new paths of a rename.

Tracked changes must be collected with rename detection disabled so a rename is Evidence for deletion of the old path plus addition of the new path.

The result must use Repository-relative `/` paths, contain no duplicates, and be sorted deterministically.

Untracked files ignored by standard Git ignore rules must not be included. Tracked files remain tracked Evidence even if their path later matches an ignore rule.

## Git Command Boundary

Use Python standard-library process execution with argument lists.

Git commands that return path lists must use NUL-delimited output (`-z`) so path parsing does not depend on whitespace, quoting, or line boundaries. Parsed paths must then be normalized to Repository-relative `/` form.

Do not invoke shell command strings or run Git commands that modify Repository state.

Failure semantics:

- if `repo_root` is inside a valid Git worktree but is not the top-level directory of that worktree, raise `ValueError`;
- if Git cannot be executed, `repo_root` is not a Git worktree, `baseline.head` cannot be resolved in the Repository, or another required Git command fails, raise `RuntimeError`.

## Scope

Do not implement:

- scope PASS/FAIL decisions;
- verification command execution;
- exact/hash invariant checks;
- Evidence JSON assembly;
- final PASS/FAIL gate;
- Worker execution;
- CLI behavior;
- HC-004 or later behavior.

## Contract Baseline Preparation

Before Worker execution, tests must be added and committed with this Task.

Tests must cover at minimum:

- clean baseline captures HEAD;
- Repository subdirectory is rejected when supplied as `repo_root` to either public API;
- unstaged tracked modification rejects baseline;
- staged change rejects baseline;
- untracked non-ignored file rejects baseline;
- untracked ignored file does not reject baseline;
- untracked ignored file is not reported as a changed path;
- a modified tracked file is still reported when its path matches an ignore rule;
- unchanged Repository state after baseline returns an empty tuple;
- modified tracked path is reported;
- a tracked change committed after `baseline.head` is still reported;
- staged addition is reported;
- untracked non-ignored path is reported;
- deleted tracked path is reported;
- rename reports both old and new paths;
- changed paths are unique and sorted;
- a changed path containing spaces is reported exactly;
- Git command failure fails closed;
- an invalid or unavailable `baseline.head` fails closed.

Tests may use temporary Git repositories only and must not modify the real Harness Repository except for the committed test file.

The Worker must not modify committed tests.

## Acceptance Criteria

- `GitBaseline` is a frozen dataclass containing the captured HEAD commit.
- Both public APIs require the actual Git top-level Repository root.
- Dirty tracked, staged, unstaged, or untracked non-ignored state is rejected.
- Untracked ignored files do not make a baseline dirty and are not returned as changed paths.
- Tracked changes remain Evidence even if their path matches an ignore rule.
- Git command failures fail closed.
- `get_changed_paths()` detects tracked, committed-after-baseline, and untracked changes relative to the baseline.
- Deleted paths are included.
- Renames expose both old and new paths.
- Returned paths are Repository-relative, normalized, unique, and sorted.
- Git path-list output is parsed with NUL delimiters rather than whitespace or line splitting.
- Existing HC-001 and HC-002 behavior and tests remain passing.
- No third-party dependency is added.
- During Worker execution, only `tools/harness_core.py` may be modified.
