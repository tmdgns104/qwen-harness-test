# HC-002 - Path / Scope Matcher

## Status

APPROVED - READY FOR CONTRACT BASELINE PREPARATION

## Problem

HC-001 can parse `Allowed Changes` and `Forbidden Changes` into a `ChangeScope`, but the Harness Core does not yet have a deterministic way to decide whether a Repository-relative path matches that scope.

Past Evidence Collector experiments also showed that `src/**` recursive patterns can be handled incorrectly if path matching is left to an adhoc implementation.

## Goal

Add a small, deterministic path / scope matcher to the Harness Core so later Git changed-file Evidence can be checked against `ChangeScope` without LLM reasoning.

## Required API

Add the following functions to `tools/harness_core.py`:

```python
path_matches(path: str, pattern: str) -> bool
is_path_allowed(path: str, scope: ChangeScope) -> bool
```

## Pattern Contract

Inputs are Repository-relative path strings or Task pattern strings.

Before comparison, normalize both `path` and `pattern` by replacing backslashes `\` with forward slashes `/`.

Support only these pattern forms:

1. Exact path
   - `tools/harness_core.py` matches only `tools/harness_core.py`.

2. Recursive directory pattern ending in `/**`
   - `src/**` matches `src/app.py`.
   - `src/**` matches `src/pkg/util.py` .
   - `src/**` does not match `src2/app.py` .
   - `src/**` does not match the bare path `src`.

No other glob syntax is supported in HC-002.

Patterns such as `*.py`, `src/*.py`, `src/**a`, or a standalone `**` must not be interpreted as wildcards. They are treated as exact literal paths and therefore do not broaden scope.

The special English phrase `all other Repository files` is not a wildcard syntax for `path_matches()`. It is treated as a literal pattern.

## Scope Decision Contract

`is_path_allowed(path, scope)` must use the following deterministic order:

1. If the path matches any `scope.forbidden` pattern, return `False`.
2. Otherwise, if the path matches any `scope.allowed` pattern, return `True`.
3. Otherwise, return `False`.

Therefore Forbidden Changes always win over Allowed Changes, and a path that is not explicitly allowed is denied by default.

## Scope

This Task is limited to path pattern matching and scope allow/deny decisions.

Do not implement:

- Git commands;
- Git baseline or changed-file collection;
- file existence checks;
- path canonicalization against the filesystem;
- JSON output;
- verification command execution;
- exact / hash invariant checks;
- Evidence assembly;
- CLI behavior;
- HC-003 or later Harness Core behavior.

## Contract Baseline Preparation

Before Worker execution, HC-002 tests must be added and committed with this Task specification.

The committed tests must cover at minimum:

- exact path match and mismatch;
- `dir/**` direct child match;
- `dir/**` nested child match;
- similar prefix does not match (for example `src/**` vs `src2/a.py`);
- bare directory does not match `dir/**`;
- backslash / forward-slash normalization;
- unsupported wildcard syntax does not broaden scope;
- Forbidden-over-Allowed precedence;
- Allowed match returns allow when no Forbidden pattern matches;
- default deny when no Allowed pattern matches.

The Worker must not modify the committed tests.

## Forbidden Changes

## Acceptance Criteria

- `path_matches()` supports exact path matching.
- `path_matches()` supports trailing `/**` recursive directory matching.
- `path_matches()` normalizes backslashes to forward slashes before comparison.
- Unsupported wildcard syntax does not broaden scope.
- `all other Repository files` is not treated as special wildcard syntax.
- `is_path_allowed()` checks Forbidden before Allowed.
- `is_path_allowed()` allows a path that matches Allowed when no Forbidden pattern matches.
- `is_path_allowed()` denies paths that match no Allowed pattern.
- Existing HC_001 behavior and tests remain passing.
- `ChangeScope` remains a frozen dataclass.
- No third-party dependency is added.
- During Worker execution, only `tools/harness_core.py` may be modified.
