# HC-004B - Deterministic Verification Command Execution

## Status

COMPLETE - VERIFIED - commit eb2fd68

## Parent

HC-004 - Verification Command Runner

## Problem

HC-004A produces raw approved verification command strings, but those commands still require deterministic process execution. Execution must not depend on LLM interpretation, implicit shell behavior, or self-reported PASS claims.

## Goal

Execute only commands contained in a VerificationContract, in Repository-document order, and return immutable structured Evidence containing each raw command, actual exit code, stdout, and stderr.

## Proposed Public Contract

Add a frozen dataclass:

`VerificationCommandResult(command: str, exit_code: int, stdout: str, stderr: str)`

Add a public executor:

`run_verification_commands(contract: VerificationContract, cwd: str) -> tuple[VerificationCommandResult, ...]`

## Command Execution Contract

- Commands come only from `VerificationContract.commands`.
- Execute commands in contract order.
- Use `subprocess.run()` with `shell=False`.
- Use an argv sequence rather than shell command execution.
- Capture stdout and stderr as text.
- Run each process in the explicitly supplied `cwd`.
- Use `check=False` so non-zero exit codes remain observable Evidence.
- A non-zero exit code is returned unchanged and does not become a Harness PASS or FAIL judgment.
- Continue to later approved commands after an ordinary non-zero exit code.
- A process-start failure is different from a completed non-zero process and must fail closed.

## Command Tokenization Boundary

HC-004B defines a small portable argv grammar; it does not emulate Windows CMD, PowerShell, or POSIX shell syntax.

- Tokenize each approved command with standard-library `shlex.split(command, posix=True)`.
- The tokenizer is used only as the Harness argv grammar, not as shell emulation.
- Quoted arguments containing spaces must remain one argv element.
- Empty commands are invalid.
- Malformed quoting is invalid.
- Standalone shell control operators `&&`, `||`, `|`, and `;` are unsupported and must raise `ValueError` before process execution.
- Do not expand environment variables.
- Do not perform redirection, pipelines, command chaining, glob expansion, or shell built-ins.
- Do not invoke `cmd.exe`, PowerShell, Bash, or another shell implicitly.
- Platform-specific shell syntax requires a separate approved contract.

## Fail-Closed Rules

Raise `ValueError` before execution when:

- the `VerificationContract` contains no commands;
- a command is empty;
- command tokenization fails because quoting is malformed;
- an unsupported standalone shell control operator is present.

Raise `RuntimeError` when:

- the operating system cannot start an approved process, including executable-not-found and other `OSError` process-creation failures.

Do not invent a synthetic exit code for a process that never started.

## Responsibility Boundary

- Do not parse Markdown; HC-004A owns that responsibility.
- Do not invent or modify verification commands.
- Do not use `shell=True`.
- Do not perform changed-path scope checks.
- Do not assemble final HC-006 Evidence.
- Do not decide final Task PASS or FAIL.
- Do not retry failed commands.
- Do not invoke an LLM, Worker backend, OpenCode, Ollama, or Codex.
- Do not implement HC-005 behavior.

## Required Tests

Tests must cover at minimum:

- one successful command captures raw command, exit code 0, stdout, and stderr;
- multiple commands execute in contract order;
- a non-zero process exit code is returned unchanged;
- execution continues to later approved commands after an ordinary non-zero exit;
- quoted arguments containing spaces are preserved as one argv argument;
- execution uses `shell=False`, text capture, and the supplied cwd;
- empty `VerificationContract` fails before process execution;
- malformed quoting fails before process execution;
- standalone shell control operators fail before process execution;
- process-start `OSError` becomes fail-closed `RuntimeError`;
- returned result objects are frozen;
- existing HC-001 through HC-004A tests remain passing.

Tests should mock process execution where exact subprocess call arguments are the contract under test. A minimal real-process smoke test may be used only when deterministic and platform-safe.
