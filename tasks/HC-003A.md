# HC-003A - Git Execution and Repository Root Validation

## Status

APPROVED - READY FOR CONTRACT BASELINE PREPARATION

## Parent Task

HC-003 - Git Baseline and Changed-File Evidence

HC-003 was decomposed after objective Worker failures. HC-003A implements only the shared Git execution and Repository-root validation primitive needed by HC-003B and HC-003C.

## Problem

The HC-003 Worker attempts showed two deterministic boundary failures:

- Git may return a Windows worktree root using `/` while Python receives the same path using `\`, so raw string comparison can reject a valid Repository root.
- If Git cannot be executed, process creation can raise `OSError` / `FileNotFoundError` before a Git return code exists.

These failures must be handled centrally before baseline capture or changed-path collection is implemented.

## Goal

Add a small internal Git execution helper and a Repository-root validation helper that:

- execute Git without a shell;
- fail closed with `RuntimeError` when Git cannot execute or a required Git command fails;
- distinguish a valid worktree subdirectory from the actual top-level Repository root;
- compare equivalent Windows path spellings correctly.

Do not implement baseline capture or changed-path Evidence in this Task.

## Required Internal API

```python
def _run_git(
    repo_root: str,
    args: tuple[str, ...],
    *,
    text: bool = True,
) -> subprocess.CompletedProcess:
    ...

def _require_git_top_level(repo_root: str) -> str:
    ...
```

`_run_git()` may use a more precise `CompletedProcess` type annotation if useful, but must preserve the behavior below.

## Git Execution Contract

`_run_git()` must:

- execute `git -C <repo_root> ...` using Python standard-library process execution;
- pass arguments as a list or tuple, never as a shell command string;
- use `shell=False` or the subprocess default equivalent;
- capture stdout and stderr;
- return the successful `CompletedProcess`;
- raise `RuntimeError` if process creation fails, including `OSError` / `FileNotFoundError`;
- raise `RuntimeError` if Git returns a non-zero exit code;
- preserve `text=True` behavior when requested and not call `.decode()` on text output;
- support `text=False` for later NUL-delimited byte output without itself parsing paths;
- never run a Git command that modifies Repository state.

## Repository Root Contract

`_require_git_top_level()` must:

- use `_run_git()` with `rev-parse --show-toplevel`;
- accept the actual top-level directory of a Git worktree;
- return the Git top-level path;
- reject a subdirectory inside a valid worktree with `ValueError`;
- surface a non-Repository path as `RuntimeError`;
- compare the supplied path and Git top-level path by normalized filesystem identity rather than raw slash spelling;
- work correctly on Windows when one spelling uses `\` and Git output uses `/`;
- never modify Repository state.

- Git process creation failures fail closed as `RuntimeError`.

- Non-Repository paths raise `RuntimeError`.
